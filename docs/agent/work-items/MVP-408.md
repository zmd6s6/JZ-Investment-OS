## Implemented vertical

Independent `/calendar` weekly portfolio/watchlist panel → protected mutation API `/api/v1/runtime/weekly` → SQL frozen authorization → real production Worker → immutable report/history/replay. Preview binds scope/source/hash; save is paused. ENABLE, PAUSE and terminal REVOKE require separate explicit confirmation, CAS version and UUID receipts. Daily/monthly/opportunity permissions confer no weekly authorization.

Every Monday–Sunday date has an explicit OPEN/CLOSED manifest tied to imported source/version/hash and immutable normalized rows. The server rereads persisted sessions and exact coverage independently; a boolean cannot establish provenance. OPEN entries must exactly match persisted sessions. CLOSED entries remain **SOURCE_DECLARED**, not exchange/provider verified; users must not interpret them as an independently licensed official calendar. No weekends/holidays are inferred. Complete elapsed weeks use the explicit market timezone and last imported session. Explicit all-CLOSED weeks skip without inventing a close.

Portfolio positions and selected watchlist identities are frozen. Local source ownership/hash and four timestamps gate visible evidence. Current book/knowledge/recording times are distinct from the historical week close. Historical holdings/returns, macro/industry, new risk assessment and reentry judgment remain UNKNOWN/NOT_PROVIDED. Only actual comparable prior captures are compared. No outbound provider/model capability is injected; budgets/profiles are zero/empty. No Analysis/Decision/Approval/Execution or Policy/Strategy mutation is offered; auto_trade=false and Risk Veto are unchanged.

Worker polls at most50 configurations and plans at most4 periods, using a serialized persisted fair cursor. Actual final authorization/scope/calendar checks and report/reference/evidence/Event/Audit/Outbox/TaskRun success commit in one transaction. Local failed attempts roll back effects, leave bounded failed TaskRun history and stop after3. Unique schedule/week prevents duplicate effects across revisions and two Workers. Restart reconstructs progress from SQL.

## Owner-visible procedure

1. Open `/calendar`, section “周度组合复核”. Choose an existing nonempty portfolio and explicitly select any watchlist members.
2. Choose an authorized imported SSE/SZSE calendar. Enter task name, full Monday–Sunday range, the source's explicit per-date `YYYY-MM-DD,OPEN` or `YYYY-MM-DD,CLOSED` entries, local quote/evidence source names, authorization validity and report retention.
3. Confirm local full-week scope and click “预览完整周度授权（不保存）”. Verify frozen identities, calendar/hash and boundaries; then confirm the preview and “保存周度授权为暂停”. No report runs while paused.
4. Separately confirm the saved authorization and “启用周度复核”. After a complete covered elapsed week, refresh status and open “周报冻结快照”. Inspect original report ID/hash, actual source Evidence/four times, Core/Tactical, reference valuation, unknowns and no-auto-trade notice. Refresh/reload reads the same persisted report.
5. Explicitly pause or permanently revoke. Revocation cannot be undone and cannot erase old reports. A new authorization needs its own preview/save/enable.

Failure paths: partial week, missing/extra/contradictory manifest, source/version/identity drift, CAS mismatch, absent/expired authorization, or stale/missing evidence fail closed or show named unknowns. Unknown write receipts require a read-only refresh before explicit same-request retry. Invalid/expired report IDs never substitute another report. Failed reads clear old report bodies and disable unconfirmed writes; pagination failures retain already loaded rows with retry feedback. Bounded pages keep older revoked authorizations and history reachable.
