# PR-01 — Domain Kernel, Policy & State Machines

- State: `READY_FOR_REVIEW`
- Depends on: PR-00 foundation
- Governing spec: `INVESTMENT_OS_MASTER_SPEC.md`, especially sections 2, 7, 8, 10, 15, 18, and 21
- Business behavior permitted: pure domain validation and transitions only

## Objective

Establish a deterministic, framework-free domain kernel that fails closed for invalid financial
values, inconsistent Policy, illegal state transitions, Risk Veto bypass, invalid approval, and
Learning Engine authority escalation.

## Delivered

- [x] Closed domain enums for Action, risk intent, Core/Tactical buckets, and governed states
- [x] Exact `Decimal` values, UTC timestamp normalization, Weight/Quantity validation
- [x] Core plus Tactical equals total position invariant
- [x] Immutable Investment Policy and PolicyVersion domain objects
- [x] Strict, versioned Pydantic Policy input boundary with cross-field checks
- [x] Explicit Instrument, Thesis, Decision, and Strategy Proposal state machines
- [x] Risk Veto gate for BUY/ADD and human approval gate for Decisions
- [x] Learning Engine proposal-only authority through `HUMAN_REVIEW`
- [x] Stable domain error codes and transition reason codes
- [x] Generated Investment Policy JSON Schema and drift check
- [x] Unit and Hypothesis property tests
- [x] Separate domain line and branch coverage enforcement
- [x] ADR-0011

## Acceptance criteria

1. Illegal transitions return a coded domain error and never mutate state.
2. Inconsistent or unsafe Policy documents fail closed, including unknown fields.
3. V1 Policy cannot set `auto_trade=true` or disable human approval.
4. A Risk Veto blocks risk-increasing approval; REDUCE/EXIT require an explicit exception record.
5. Decision execution requires valid, unexpired, unrevoked human approval without material drift.
6. Learning Engine cannot approve, reject, schedule, activate, or retire Strategy.
7. Core and Tactical quantities cannot disagree with the total Position.
8. Domain has no FastAPI, Pydantic, SQLAlchemy, DSA, LLM, worker, or UI dependency.
9. Domain line coverage is at least 90%; branch coverage is at least 85%.

## Acceptance scenario slices

- S3 kernel: Risk Veto blocks BUY from entering `PENDING_APPROVAL`.
- S5 kernel: BROKEN Thesis can recover only through a new version with major Evidence and full review.
- S10 kernel: approval and execution transitions reject non-human, expired, revoked, or drifted input.
- S11 kernel: Learning Engine cannot cross the human review authority boundary.

Full S3, S5, S10, and S11 workflows remain scheduled for their roadmap stages.

## Out of scope

- database entities, persistence, audit writer, migrations, and concurrency;
- DSA/Evidence ingestion and runtime Agents;
- actual Risk Engine, Position Sizing Engine, approval API, or execution adapter;
- scheduler and UI;
- activation of any real Investment Policy.

## Known limitations and rollback

The Policy is an explicitly labeled `TEST_DEFAULT`; real investment limits remain a human decision.
State-transition results are ready for PR-02 persistence but are not yet written to an audit log.
There are no migrations or production data. Rollback removes the PR-01 modules, Schema/config, tests,
and ADR together.

The first remote run identified a false positive where Gitleaks scanned one-way fingerprints inside
the detect-secrets baseline. `.gitleaks.toml` excludes only that baseline file; both independent
secret scanners pass after the correction.
