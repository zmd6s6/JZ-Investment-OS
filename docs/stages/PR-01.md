## 验收标准

1. 非法转换返回带代码领域错误，且绝不修改状态。
2. 不一致或不安全的 Policy 文档失败关闭，包括未知字段。
3. V1 Policy 不得设置 `auto_trade=true` 或禁用人工批准。
4. Risk Veto 阻止提高风险的批准；REDUCE/EXIT 需要显式例外记录。
5. Decision 执行要求有效、未过期、未撤销且无实质漂移的人类批准。
6. Learning Engine 不得批准、拒绝、安排、激活或退休 Strategy。
7. Core 与 Tactical 数量不得与总 Position 不一致。
8. 领域层不得依赖 FastAPI、Pydantic、SQLAlchemy、DSA、LLM、Worker 或 UI。
9. 领域行覆盖率至少 90%，分支覆盖率至少 85%。

## 审查 blocker 修复

PR #1 的所有者审查发现 Boolean `risk_veto=false` 使缺失 Risk Assessment 与 Risk PASS 无法区分。Decision 闸门现使用显式 `RiskGateState`：

- `UNKNOWN` 为默认值，在进入 `PENDING_APPROVAL` 前失败关闭；
- BUY 与 ADD 必须为 `PASS`；
- `VETO` 阻止增加暴露；
- Veto 下的 REDUCE 和 EXIT 仍要求记录降低风险例外。

命名测试覆盖缺失 assessment、显式 BUY PASS、ADD PASS 和 REDUCE/EXIT Veto 例外。另一个独立的 PR-00 完成记录不一致也已更正。审查中关于可审计 REJECTED actor 和确定性 EXPIRED TTL guard 的非阻塞建议，仍被明确安排在实现批准记录和过期的 PR-07。
