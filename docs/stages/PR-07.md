## 目标

交付可审计的 Decision 路径，具有明确的 CIO 关卡、不可变人工批准动作、模拟/手工执行记录和完整
Decision Journal。全部工作使用合成或获授权去标识化数据。V1 保持 `auto_trade=false`：禁止实盘经纪商
订单和凭证。

## 交付物

- [x] CIO 聚合：将 Thesis/投资质量、时点、组合适配、风险和 policy/数据充分性保留为明确关卡，而非综合得分
- [x] 不可变 Decision 聚合、状态转换、持久化和带类型的只读 API
- [x] 不可变人工 `APPROVE`/`REJECT`/`REVOKE` 记录，具失败闭合的批准 TTL 语义
- [x] 绝对拒绝带类型实盘订单提交的 `DisabledLiveExecutionAdapter`
- [x] 链接有效人工批准的不可变模拟/手工执行记录
- [x] 完整 Decision Journal、审计轨迹和合成端到端 S10 覆盖
- [x] 阶段证据和项目状态更新

## 验收标准

1. CIO 聚合不能仅凭时点将弱投资质量变为 BUY/ADD，也不能在 Thesis、Portfolio、Risk、Policy 或
   数据关卡失败时因时点很强而变为 BUY/ADD。
2. 每个 Decision 保留决策时使用的准确 Evidence、Thesis/Policy/Strategy/Prompt 和仓位规模计算版本、
   风险结果、Core/Tactical 动作、未知项、异议、原因和复核计划。
3. 具名人工动作只追加。只有 Policy TTL 内当前有效的 `APPROVE` 能推进 Decision；拒绝、撤销、到期
   或实质输入/价格漂移均不能绕过。
4. Risk Veto 持续阻塞 BUY/ADD 和敞口增加；CIO 与批准不能覆盖它。REDUCE/EXIT 保留独立记录的降风险路径。
5. V1 不能提交实盘订单。唯一的实盘适配器拒绝每一个请求；模拟和手工记录保持为链接有效批准的独立、
   不可变执行记录。
6. 合成 S10 端到端覆盖从 Evidence 经 Decision、人工动作到模拟/手工执行重建审计链。正常、失败和边界
   测试覆盖每项新增行为。

## 人工决定和范围外事项

所有者必须在合成测试外使用前选择真实批准主体、TTL、价格漂移容忍度、Portfolio 数据和投资 policy
限制。经纪商集成、凭证、实盘执行或改变 `auto_trade=false` 均需要新的/替代的 ADR 和明确人工授权；
没有一项在本阶段范围内。
