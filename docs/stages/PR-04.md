- 允许的业务行为：不可变 Thesis 创建/版本化、Evidence 支持的影响评估、受控监控/失效、时间旅行读取和仅内部读 API

## 目标

交付 Evidence-first Thesis Engine 纵切。每个新 ThesisVersion 只追加、具有确定性语义 diff 和溯源，并保持先前版本可读。新 Evidence 只能通过显式确定性条件提出影响；绝不覆盖 Thesis，也不产生 Decision、批准、执行或实盘交易行为。

## 交付物

- [x] 严格 ThesisVersion 内部 Schema 及 Evidence 引用、版本谱系、监控和失效条件的纯领域不变量
- [x] 具只追加持久化和乐观当前指针更新的 Thesis 创建/版本/diff 服务
- [x] 仅在实质、Evidence 支持变化时创建新版本的 Evidence-impact 评估；未变化 Evidence 不得创建空版本
- [x] 确定性监控和失效条件评估，包括无 Decision 或订单路径的显式 BROKEN 升级候选
- [x] 时间旅行 Thesis 读取和 `/api/v1/theses/{instrument_id}` 及版本历史读 API
- [x] 合成单元、集成、契约及 S5 回归夹具
- [x] 数据血缘、状态和验证证据

## 验收标准

1. ThesisVersion 记录不可变、内容寻址、唯一且版本单调增长；修正后先前版本仍可读。
2. 每个事实 pillar、catalyst、risk 或实质更新均保留有效 Evidence 引用；缺失或不可用 Evidence 失败关闭。
3. 相同输入的语义 diff 确定，未变化影响不得制造新 ThesisVersion。
4. Evidence 支持的失效创建新的 `BROKEN` ThesisVersion 及机器可读的强制复核/REDUCE-or-EXIT 候选，而不创建 Decision、批准、执行或订单。
5. 请求 as-of 时间读取仅返回当时最新可用 ThesisVersion，绝不重写历史含义。
6. API 拒绝畸形或指令式 payload；夹具仅为合成。
7. S5 证明旧版本未改变，且历史 Decision 可保持固定 Thesis 版本引用。
