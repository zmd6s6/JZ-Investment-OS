## 目标

建立后续阶段所需的 PostgreSQL 持久化基础，而不把投资权力移入基础设施代码。数据库写入与 Outbox 写入必须原子化；可审计记录保持只追加；受治理的可变指针使用乐观并发；任务重试经幂等性获得恰好一次的业务效果。

## 验收标准

1. 空 PostgreSQL 上 `alembic upgrade head` 成功并创建所需核心表、约束和索引；已测试降级至 base 后重新升级。
2. 失败的 Unit of Work 不留下业务写入，也不留下 Outbox/audit/event 记录。
3. 已提交 Unit of Work 原子地持久化业务写入和 Outbox 记录。
4. 以同一幂等键重复成功逻辑任务，不重复业务效果并返回原完成 TaskRun。
5. 同一逻辑任务并发执行被事务范围 PostgreSQL advisory lock 拒绝。
6. 对 Position、Thesis 当前指针、Decision 状态和 Policy 当前版本指针的过期写入，以带代码乐观并发错误失败。
7. Audit/event 历史不能通过支持的 repository 或直接数据库写入更新或删除。
8. 集成测试仅用合成数据并针对 PostgreSQL 16 运行。
9. 领域层保持独立于 SQLAlchemy、Alembic、FastAPI、Worker 和 adapter 代码。

## 已完成范围

修订 `20260917_0001` 创建全部 35 张核心表及规范化 Evidence 引用表。它强制 UUID 键、精确 numeric、时区感知时间戳、核心唯一性和外键、只追加 audit/event 与不可变工件保护，以及乐观版本列。聚焦 ORM repository 持久化已校验的 Policy、Position、Thesis 和 Decision 变化；业务状态合法性留在领域层。

可靠任务切片取得事务范围 advisory lock，校验时区感知业务时间，拒绝幂等键输入漂移，记录尝试和已清理失败，并在一个 Unit of Work 中提交业务、event、audit 和 Outbox 写入。Compose 拓扑现在在 API/Worker 启动前运行 Alembic 一次性任务。

## 验收场景切片

- S12 基础设施切片：以同一键重复成功任务会复用已完成 TaskRun 且不重复业务效果；锁竞争、重试失败、输入漂移和 rollback 路径均为命名集成测试。

完整 Daily 任务的 Evidence/Decision/报告幂等性仍正确安排在 PR-08。

## 已知限制与回滚

后续阶段仍拥有 Schema-only 核心表的业务 repository 和工作流。不存在 DSA 摄入、运行时 Agent、批准 API、执行路径或真实 Policy 激活。测试和 Compose 中唯一凭据都明确标为本地占位符。

空开发数据库可降级至 `base`，并一同移除 PR-02 模块与依赖。已填充数据库则停止写入端，如需要将已验证备份恢复到独立数据库，并发布经审查的前向修复；绝不重写已接受迁移或删除审计历史。详见 `docs/runbooks/migrations.md`。
