## Objective

Introduce a replaceable research-provider boundary and an evidence-first ingestion vertical slice.
External payloads remain untrusted data: upstream schema drift and failures fail closed, historical
records remain readable, and deterministic code—not an LLM—derives the initial feature set.

## Deliverables

- [x] Versioned `ResearchProviderPort` and internal research-artifact DTOs
- [x] DSA adapter mapping behind the application port, with timeout/schema-drift failure handling
- [x] Strict ingest request/response schemas and an authenticated-in-later-stage internal API seam
- [x] Immutable ResearchArtifact/Evidence persistence with content-addressed deduplication
- [x] Deterministic evidence quality and freshness evaluation, including stale/conflict outcomes
- [x] Deterministic Feature Engine interface and minimal provenance-preserving feature snapshot
- [x] Synthetic contract, unit, integration, and security fixtures for S8, S13, S14, and S15
- [x] Data-lineage records, documentation, and status/verification evidence

## Acceptance criteria

1. A provider adapter exposes only internal versioned DTOs; no DSA private type, table, or module
   reaches domain or application code.
2. Valid synthetic artifacts normalize into immutable, content-addressed Evidence and retain
   provider reference, source schema version, business times, and raw-content hash.
3. Re-ingesting identical content is deduplicated; corrections are appended rather than overwriting
   prior Evidence.
4. Missing, unknown, stale, conflicting, or schema-drifted provider data fails closed with explicit
   structured outcomes and cannot manufacture high-quality Evidence.
5. Deterministic feature snapshots use only Evidence available at the requested as-of time and retain
   an input hash and feature-set version.
6. The ingest API rejects malformed or prompt-injection-like external payloads as untrusted data;
   quoted external text never changes application behavior.
7. Tests use only synthetic data and demonstrate S8, S13, S14, and S15 slices.

## Risks and human decisions

PR-03 uses synthetic contract fixtures and does not enable production DSA connectivity. Selecting a
real provider account, license, retention policy, or cost boundary remains a human decision; this
does not block the safe adapter and fixture implementation.
