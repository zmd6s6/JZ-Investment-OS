## 目标

交付个人每日运营闭环：显式市场日历的调度工作、持久的重放和失败可见性、可供人阅读的报告，以及四个
个人只读 UI 视图，且不创建实盘执行路径。

## 交付物

- [x] 日、周、月、季任务定义，具备明确的市场时区/日历
- [x] 持久幂等性、咨询锁、as-of 重放、有限恢复和可见 TaskRuns
- [x] 合成日、周、月报告，标示事实、计算、判断、假设和人工决定
- [x] React/TypeScript `web/` 工作区以及 Portfolio、Opportunities、Watchlist 和 Decision Journal 页面
- [x] 显著的模拟、数据 as-of、证据新鲜度、Risk Veto、待批准和运行异常指示器
- [x] S12 与每个面向用户的调度器/UI 安全状态的正常、失败和边界覆盖

## 验收标准

1. 任务绝不使用服务器本地时间作为业务时间；每个任务均有显式市场日历和 `as_of` 语义、幂等键、
   咨询锁、持久 TaskRun、事务性 outbox 事件和重放路径。
2. 同一逻辑 Daily 任务的重试或并发调用仅产生一次业务效果；失败有限、经清洗、可持久化且可见。
3. 报告区分事实、确定性计算、Agent 判断、假设和人工决定，绝不将建议呈现为已执行交易。
4. 四个 UI 页面均可使用合成/去标识化数据，并显著保留 V1 模拟/禁止自动交易、新鲜度、Veto、批准和异常信号。
5. 调度器触发、API/UI 动作或报告路径都不能绕过 Risk Veto、有效人工批准、不可变历史或禁用的实盘执行。
