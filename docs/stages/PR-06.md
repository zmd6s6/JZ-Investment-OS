## 目标

仅使用合成或获授权去标识化输入，交付确定性的 Portfolio、Risk 和 PositionSizing 行为。本阶段
必须保留 Core/Tactical 分离，在批准前预留待处理容量，防止 Risk Veto 被覆盖，且不创建 Decision、
批准、执行、经纪商或实盘交易路径。

## 交付物

- [x] 不可变 Portfolio 快照和 Core/Tactical 持仓
- [x] 针对单一标的、行业、总敞口、现金和待处理容量的确定性 portfolio-fit 检查
- [x] 带版本的硬/软 Risk 标记和不可变 PASS/VETO 评估
- [x] 纯函数、带公式版本的 PositionSizing Engine，使用 Decimal 输入哈希、降低风险的手数取整和约束上限原因
- [x] 批准前容量预留和持久化映射
- [x] S3、S4、S6 和 S7 的合成正常、失败、边界及性质测试
- [x] 阶段证据和项目状态更新

## 验收标准

1. Core 和 Tactical 数量、成本、动作和原因保持分离，其数量始终与总 Position 对账一致。
2. 每次 BUY/ADD 容量计算均考虑当前和待处理敞口，且不得超过单一标的、行业、总敞口或最小现金限制。
3. 硬 Risk Veto 具备原因代码、Evidence 引用、到期时间和解除条件；它将 BUY/ADD 仓位规模计算增量
   强制为零，且不能被 CIO 或其他组件覆盖。
4. 仓位规模计算是纯函数、公式带版本的 Decimal 计算。相同输入返回相同输出和哈希；手数取整只能降低风险。
5. REDUCE/EXIT 遵循独立的降风险路径，不会被负的新风险容量阻塞。
6. S3、S4、S6 和 S7 使用合成夹具自动化。不得有路径创建 Decision、批准、执行、经纪商请求、供应商凭证或实盘交易。

最终风险代码治理、任何供应商授权或任何执行模式需要人工授权，均不在范围内。Decision、批准、执行、
调度器、UI 和 Learning 工作流仍由后续阶段负责。
