# ADR-0024 — 分析固定引用已保存的投资逻辑

- 状态：Accepted（主规范与 P6 既有范围内的输入 / 版本工程决策）
- 日期：2026-10-21
- 补充：ADR-0003、0004、0005、0006、0018、0019、0023；不改写已接受 ADR

## 背景

分析请求已有 thesis_version_id / thesis_state 字段，但产品未装配数据库读取，默认 VALID。
这会让长期记忆缺失看起来已经通过逻辑门，也让已有 BROKEN 无法参与复核。
本纵切先交付真实 Thesis 主表的输入关联，不把它冒充完整 Risk / Decision 主表落库。

## 决策

- 增加类型化只读 Thesis 输入端口。读取 investment_thesis 的已发布指针，再选择该发布范围内、
  created_at 不晚于分析时点的最新版本；业务评估时间、关联证据 available_at / ingested_at 不能来自未来。
  不读取未发布版本，不自动创建、修复或更新指针。该时点无版本时保存明确的空快照并按 UNKNOWN 处理。
- 校验指针 / 父版本归属与序号、领域内容、规范 hash、正规化证据引用集合和标的范围。
  结构损坏、引用缺失或未来资料拒绝分析，不退回其他版本、不默认 VALID。
- 入队前固定版本 ID / 父版本 / 序号 / 内容 / hash、支持资料 ID / hash / 时间 / 新鲜度。
  沿用既有不可变输入与队列守卫；不新建表或迁移。后续指针变化不影响排队运行与旧报告。
  显式重新发起是新运行，重新读取当时可用版本。历史报告没有快照时不补写。
- 同一快照传给八角色和确定性 CIO / 仓位输入，影子 Decision 保存实际版本 ID / hash / 状态。
  历史主张是不可信上下文，不自动扩充本次可引用证据集合；原有证据门继续限制 observation。
  Prompt 系统文本、AgentOpinion 协议、投资权重和政策限额不变。
- 保存的状态与本次有效状态区分：支持资料陈旧 / 到期时，非 BROKEN 版本按 UNKNOWN 使用；
  已知 BROKEN 不因资料陈旧被弱化。入队时新鲜的支持资料在执行前到期则停止，不调用模型或换资料。
  不改写原始 Thesis 状态或历史证据新鲜度。
- 按主规范 §6.3，已有持仓的 BROKEN 必须产生 REDUCE 复核候选，同时明确 Core / Tactical 的实际非空桶。
  这不是批准、下单或已计算可成交数量；缺价格仍显示缺失，不编造数量、不绕过任何执行闸门。
- 新 Worker 对缺少 Thesis 快照的旧请求明确失败，不自动读取当前版本补齐。
  UI 区分旧报告未记录、该时点无版本、固定版本以及陈旧支持资料，并说明本轮未生成新 Thesis。

## 替代方案与后果

拒绝保留默认 VALID、执行时读取最新版本、把模型观点直接写成正式逻辑或创建占位 Thesis。
读取多一次短事务，快照增加有限存储；无法解释的旧队列要求用户核对后显式新建。
创建 / 修订 Thesis 的产品流程、语义 diff 的团队更新、Risk / Decision 主表链仍在 P6 后续完成。
正式 InvestmentDecision 需要真实 Policy / Strategy 引用，不能为接通外键虚构已批准版本。

## 安全、兼容与恢复

无依赖、数据库迁移、自动策略激活或交易路径；只用命名隔离库、合成内容与模型验证。
API / Worker 同步升级，回滚前停止入队并处理或取消新格式请求；旧 Worker 不得忽略快照消费。
保留所有版本 / 输入 / 报告，不追补、降级或删除历史。所有者实例的备份 / 重启仍需独立明确授权。
