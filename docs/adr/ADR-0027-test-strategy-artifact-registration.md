# ADR-0027 — 测试策略工件登记与分析版本固定

- 状态：Accepted（P6 既有追溯范围内的工程决策）
- 日期：2026-10-22
- 补充：ADR-0007、0009、0018、0019、0023、0026；不改写旧 ADR

## 背景与决策

分析已固定测试公式和 Prompt 摘要，但没有独立 StrategyVersion 身份或实际代码指纹。
本纵切将代码已经使用的工件登记为未批准的测试记录，不选择真实投资规则、不激活策略。

- 仅在明确提交分析、固定输入时，登记或复用内容相同的 DRAFT / TEST_DEFAULT 工件。
  使用已有 strategy_version 表；保存完整测试公式、八角色 Prompt 摘要及工具白名单、实际 Python 包源码指纹。
  指纹按相对路径及规范化换行后的内容计算，不冒充 Git 提交、依赖锁或模型权重版本。
- 同一登记锁串行分配既有全局版本号，内容一致复用同一身份。新增工件、审计、事件与 Outbox 同事务。
  工件登记可先于排队提交；排队失败留下可追溯的 DRAFT，不表示分析已成功，不删除历史。
- 分析输入 / 排队工作单 / 报告固定实际 ID、版本、内容摘要、状态和代码指纹。
  Worker 在行情和模型调用前读取不可变主表并核对身份、完整内容和实际运行代码；缺失或变化明确失败，
  不换用当前策略、不自动重放。进程装配后若源码热改，拒绝把磁盘新文件冒充已加载模块，须部署 / 重启后再明确新运行。
- DRAFT 工件 approved_by 必须为空，不能成为 ACTIVE / SHADOW 或人类批准的替代。
  当前公式仍 TEST_DEFAULT，allows_new_exposure 仍恒为 false；没有新增策略选择、批准、激活或交易接口。
- 旧报告只读不补写；旧排队任务缺独立策略快照时失败关闭。只读报告展示历史身份，不在 GET 中登记工件。
  正式 Decision 的政策 / 策略 / 估值和确定性仓位链仍需独立收口，不填假外键或未知权重。

## 替代方案、兼容与恢复

拒绝每次分析生成空策略、用 Git HEAD 代替实际源码、给测试规则贴已批准标签、以及执行时静默替换旧规则。
复用既有不可变守卫，无迁移、依赖或 Agent 输出协议变化。治理输入增加可选策略身份；旧无身份快照摘要保持兼容，
生产新提交必须登记。源码变化会使尚未执行的旧任务失败，这是显式的版本安全限制，不是自动升级。
回滚代码前处理活动任务；保留策略、输入和审计，不删改工件。所有者实例部署须另获备份 / 重启授权。

## 验证

覆盖同内容复用、并发登记、不同工件分配版本、登记事务回滚、不可变性、未批准身份校验、
排队后源码变化在付费调用前终止、缺失快照、历史只读不补写，以及页面测试标记与版本反馈。
主规范 §2.2、§2.3、§5、§6.5、§9、§12、§17、§18；PRODUCT-06 版本关联与只读报告验收。
