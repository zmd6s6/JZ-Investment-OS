# ADR-0019 — 持久化分析任务与真实阶段进度

- 状态：Accepted（主规范 §9、§14、§17 和 P6 既有范围内的工程决策）
- 日期：2026-10-16
- 补充：ADR-0001、0003、0004、0005、0008、0010、0014、0018；不改写旧 ADR

## 背景与决策

同步 HTTP 分析要求用户一直停留，刷新丢失等待状态，进程中断留下永久 RUNNING。
新增 additive `/analysis-jobs`：先固定输入、原子入队并立即返回运行 ID；旧 `/analysis-runs` 同步写入口兼容保留。
使用既有 PostgreSQL 和 Worker，不引入 Redis、消息服务或生产依赖。只有明确提交的任务可触发分析；不扫描持仓自动发起。

- 入队使用客户端 UUID 与请求摘要幂等；相同请求返回原运行，内容不同拒绝。输入快照、队列、事件 / 审计 / Outbox 同事务写入。
- 队列保存版本化、受校验的内部请求（证据摘录和组合，不含密钥）。Worker 使用该请求，不重新读取另一组资料或组合替换原输入。
- 工作者持有命名空间内 PostgreSQL 会话咨询锁；同任务不能并行消费。状态写入加行锁与 worker token 校验，旧工作者不得覆盖新终态。
- 进度是实际执行边界产生的只追加事件，不用计时器制造百分比。第一轮、冲突检测、第二轮、组合经理、风险、估值 / 仓位和 CIO 分别记录。
- 取消排队任务立即进入 CANCELLED；运行中取消是协作式请求，在下一个阶段边界生效。已发往供应商的请求可能完成、修复和计费，不承诺退款或撤回。
- 排队任务在重启后可继续。已经 RUNNING 但失去工作者锁的任务标为 FAILED / ANALYSIS_INTERRUPTED，不自动重放付费调用。
- 失败 / 已取消后，用户独立确认费用才能创建新的运行；沿用原证据 ID，按新时点重新验证，重新读取当前组合与配置，保留 retry_of 关联。旧运行不改写。
- Worker 的模型访问使用既有加密凭据卷、模型映射、预算和鉴权边界，不自动启用来源、不改变投资限额或任何交易批准。
- 同一次 AnalysisRun 的全部角色与修复共享运行 ID 作为预算任务归属，不再按每个角色的随机 request_id 分散单任务累计。网关请求新增可选 budget_task_id，旧调用省略时兼容 request_id；不改模型输出协议或已有额度。

## 替代方案与限制

拒绝 FastAPI 内存后台任务（重启丢失）、自动重试不确定的模型请求（重复费用）和新队列服务（运维成本）。
当前采用单 Worker 顺序处理任务，专家第一轮仍按既有协议并行；每个角色仍有既有超时和预算。
模型 / 定价 / 完整 Policy 版本固定、主表完整关联仍是 P6 后续缺口；本 ADR 不宣称完成整个阶段。

## 安全与恢复

只记录固定阶段代码、状态、时间和 ID，不写原始模型输出、凭据或外部错误到普通日志 / Outbox。
取消与重试都需既有写入鉴权、来源校验和审计。输入不可变，进度只追加。
迁移 0017 只新增任务 / 进度表和约束；已有报告不追补进度。应用回滚保留表与快照守卫；
存在任务历史时禁止破坏性降级，采用前向修复。旧版本 Worker 不消费新队列，应在回滚前确认无待处理任务。
部署前备份并检查归档；仅在合成隔离库验证升级、并发、进程中断和恢复，不删除所有者历史。
