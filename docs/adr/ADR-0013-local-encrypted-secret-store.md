# ADR-0013 — 本地加密 SecretStore 与提供方凭据引用

- 状态：Proposed
- 日期：2026-09-21
- 决策者：Codex；待人工安全审阅
- 取代：无
- 被取代者：无
- 相关阶段：PRODUCT-02

## 背景

PRODUCT-02 需要允许所有者保存模型和数据提供方配置，但主规范、ADR-0010 与产品路线图禁止将 API key 或 token 以明文写入数据库、配置、日志、审计负载、API 响应或测试夹具。

## 决策

引入应用层 `SecretStore` 端口。首个本地实现使用经认证加密的本地文件，并只从
`INVESTMENT_OS_SECRET_STORE_KEY` 读取主密钥。数据库只保存不可猜测的 `credential_ref`；API 仅返回
密钥是否已配置及固定掩码，绝不返回密钥内容。

更新或删除凭据必须与只含提供方档案 ID、credential reference 和操作类型的 Event/Outbox 记录处于同一
数据库事务。P2 的“测试”仅验证配置和凭据可用性，不发起网络请求；真实供应商网络测试与运行时调用属于
P3/P4，且需要各提供方的授权与边界审阅。

## 已考虑的替代方案

### 将密钥加密后存入 PostgreSQL

未选择。它会扩大数据库备份与审计查询的敏感边界，且使主密钥轮换和最小访问控制更难审计。

### 仅使用环境变量

未选择。环境变量可作为主密钥来源，却不能提供用户可管理的多个凭据引用、轮换记录和配置状态。

## 后果

本地单用户部署无需云 KMS；部署必须显式提供主密钥并备份加密文件与主密钥。丢失主密钥会使现有凭据无法
恢复，且必须通过轮换重新配置。

## 安全与运维影响

密钥只在 API 请求处理和 SecretStore 内存中短暂存在。文件位于被 Git 忽略的运行时目录，权限由部署账户
控制；日志、事件、Outbox、响应、错误与测试断言均不得包含密钥或可逆密文。

## 迁移与回滚

数据库迁移只添加不含密钥的配置元数据。回滚代码前必须保留加密文件；前向修复可重新绑定
`credential_ref`，但不得将秘密导出到数据库。
