# ADR-0017 — 本机配对与浏览器会话

- 状态：Accepted（所有者于 2026-10-15 明确要求按本机监听、一次配对、后续自动会话方案改进）
- 相关阶段：P6 聚焦易用性修复，不推进下一产品阶段
- 补充：ADR-0010；不修改主规范、提供方密钥存储或投资批准语义

## 背景

单人本地产品不应要求日常复制开发 Bearer。此前 API/数据库映射所有网卡，浏览器仅保存标签页令牌。
主规范 §16.3 要求写操作鉴权；不能通过删除鉴权解决体验问题。

## 决策

- 默认 Compose 将 API 和数据库发布到 `127.0.0.1`；本机 API 明确配置唯一 origin。
- 新增显式 `local_session` 模式；原 `bearer` 模式保留兼容，不能自动当成远程登录产品。
- 本地启动器检查容器身份、模式、origin 和端口绑定，通过本地 Docker 执行权限签发一次性配对码。
  不提供未鉴权的配对码签发 HTTP 接口。启动器不用读取或显示开发令牌、提供方凭据。
- 配对码为 256 位随机值，有效 120 秒，仅能交换一次；经 URL fragment 交给浏览器，发送请求前清除 fragment。
  不放入 query、日志、截图或长期存储。浏览器通过同源 JSON 请求交换 HttpOnly / SameSite=Strict Cookie。
- 会话固定有效 30 天，可跨刷新、标签页和 API 重启；浏览器断开会话时服务端立即撤销，不仅删除 Cookie。
- 会话与配对码只存 SHA-256 摘要、origin 和到期时间。使用 Python 标准库 SQLite 的事务原子消费 / 撤销，
  文件位于既有忽略的运行时卷，独立于 PostgreSQL 投资状态和提供方加密密钥。它不是新增服务或生产依赖。
- 本机模式的业务 API 读取也需会话或已有 Bearer；健康、无敏感的会话状态、配对交换是明确例外。
  精确校验 Host / origin；Cookie 写入还必须携带同源 Origin 和自定义请求头，拒绝外站、null origin、DNS 重绑定及缺失来源。
  显式 Bearer 继续用于 CLI，不被 Cookie 隐式覆盖。应用不信任转发头来判定本地授权。
- 静态 UI 无凭据；未配对只展示启动入口说明，不先加载持仓 / 设置，日常页面隐藏手填令牌入口。
- 记录不含秘密的授权事件类型；此会话只授权使用本机产品，不批准投资、不激活政策、不自动调用供应商。

## 替代方案

- 取消鉴权或任何 localhost 请求自动获权：不能阻止恶意网页 / 重绑定，拒绝。
- 长期 Bearer 放到静态包、URL query 或 localStorage：泄漏范围大，拒绝。
- 用户体系 / OAuth / 新认证服务：当前单人本机场景不需要，拒绝。
- 仅内存会话：重启丢失；仅客户端退出的签名 Cookie 不能可靠撤销，拒绝。

## 安全与运维边界

本机账户、Docker 权限、浏览器扩展和其他本机服务属于信任边界，不防拥有同等 OS 权限的恶意进程。
Cookie 不按端口隔离，采用 origin 专属 Cookie 名与服务器 origin 绑定；同源检查不替代主机隔离。
远程访问仍需专用登录、TLS 与独立威胁审查，不自动开启。备份 / 恢复后可撤销全部本机会话并重新配对。
配对失败 / 过期不会重试旧码或降级免鉴权；只需重新从本地入口打开，不更换供应商 Key。

## 迁移与回滚

无投资数据库迁移。保留原环境 Bearer 和凭据卷；新认证文件独立。回退 `bearer` 模式可继续原鉴权，
保持回环端口绑定。新 SQLite schema 只创建独立认证表，未知版本失败关闭，不修改业务数据。
