# ADR-0022 — 可跨取消与中断读取的行情尝试事件

- 状态：Accepted（主规范和 P6 已限定的审计工程决策，不改变投资治理）
- 日期：2026-10-20
- 补充：ADR-0003、0008、0010、0013、0019、0021
- 取代范围：ADR-0021 中「仅随最终结果保存行情尝试」的实现限制；旧 ADR 和旧历史不改写

## 背景

行情尝试只缓存在内存时，取消或进程中断可能丢失全部结果，无法区分未进入行情阶段与已经调用但结果未知。
供应商不提供本系统事务保证，不能承诺外部请求恰好一次或零费用。

## 决策

- 使用既有只追加 `event_log` 保存版本化 `ANALYSIS_MARKET_ATTEMPT` 事件，通过已有 aggregate 类型、运行 ID 和事件类型索引读取。
  这是特定外部副作用边界的事件账本，不替代 Portfolio / Thesis / Decision 等领域主表，也不引入通用 JSON 业务存储。
- 每次适配器尝试拥有独立 attempt ID。在进入适配器之前，提交 `STARTED` 意图；返回并校验后另行追加结果，绝不更新开始事件。
  STARTED 仅证明意图已提交，不证明 HTTP 已发出、供应商已接收或已计费；适配器可能因不支持的市场而不发 HTTP。
- 只有开始而无结果时显示「结果未知」，不补写 NO_DATA / FAILED，不用当前设置推断，不自动重放。
  这是每个来源批次的适配器尝试账本，不是逐条 HTTP 报文或供应商计费账单。
- 每个事件、对应审计与 Outbox 同事务提交；事件保存受校验的档案、顺序、查询和报价，普通审计 / Outbox 仅携带 ID、状态和内容 hash。
  不记录凭据、端点、供应商原始异常或模型正文。
- 写入锁定 AnalysisRun 行，核对冻结来源 ID / 档位 / 名称 / 类型、事件转换，以及后台任务的 worker token。
  同一开始 / 结果不得重复追加；取消请求阻止新的 STARTED，但允许保存已经发出尝试的返回结果。
  已终止运行及失去所有权的旧工作者不得再写入。
- 调用前事件写入失败则不进入适配器；调用后记录失败则停止后续来源，返回脱敏失败，已提交的开始仍然可读。
  不把数据库错误误当供应商失败并继续回退。原有显式来源顺序、普通供应商失败规则和付费确认不变。
- 增加兼容性只读 `/analysis-runs/{run_id}/market-attempts`，沿用原有鉴权模式。同步入口与 Worker 都装配持久化端口。
  新输入快照记录审计版本；旧快照不追补。页面独立、有界读取和轮询，不阻塞任务状态；重试读取仅 GET，不新建分析。

## 替代方案与后果

拒绝只在 finally 保存（进程崩溃时无法保证执行）、改写最终报告（取消时报告可能不存在且不应改历史）、新增消息服务 / 数据库表（现有事件设施足以表达这一特定边界）。
每个来源通常增加两个短事务，换取可核对的中断边界；不能消除外部调用与本地提交之间的不确定性。

## 安全、迁移与回滚

无新依赖、数据库迁移或投资规则变化；事件表既有只追加守卫继续生效。
API / Worker 同步升级；回滚前停止入队并等待或取消新版工作。回滚应用保留事件和快照，不删除或重建历史。
旧应用无法展示新账本，但不应消费忽略本次行情选择的任务。正式部署、备份与重启仍须单独授权。
验证仅使用命名隔离数据库、合成适配器和合成模型，不调用真实付费服务。
