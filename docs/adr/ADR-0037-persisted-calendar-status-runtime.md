# ADR-0037 — 可审计日历导入与无付费状态调度

- 状态：Accepted（MVP-401范围内的持久化 / 时间与调度工程决策）
- 日期：2026-10-26
- 补充ADR-0003、0008、0012，不改写旧决策；编号避开旧PR #18待集成的0017—0036。

## 背景与决策

ADR-0012的显式合成文件日历仍是工程验证基线，但所有者日常不能依赖环境变量和内部文件。
本工作项接通独立日历页面、可审计CSV导入、持久化市场会话，以及Worker对到期会话生成无付费调用的日历状态报告。
不把此报告冒充完整P8团队研究、分析、周/月复核或投资建议；这些能力仍依赖其他Work Item。

- 仅支持既有SSE、SZSE、US_EQUITIES市场与固定市场时区，不推断工作日或假日。
- CSV只接受business_date与close_at，使用显式业务日期、本地HH:MM收盘时间；拒绝重复日期、空 / 部分错误、超量及DST歧义 / 不存在时刻。规范化为UTC close_at与日期分列保存，保留来源名称、版本、hash与导入时间。
- 导入及会话只追加，数据库触发器禁止修改 / 删除；配置指针可版本化切换，显式期望版本防止并发覆盖。新导入默认暂停，须明确确认“仅状态报告、无付费调用”才能启用；暂停与配置切换同事务审计。
- 所有命令必须鉴权、请求UUID幂等，回执先于当前版本再校验；同UUID不同内容拒绝。业务变更、回执、审计和Outbox同事务。
- Worker每轮读取当前启用的持久化日历，不需要重启；无启用日历不调度。显式legacy合成文件模式仍独立保留，不自动与产品日历混用。
- 每市场 / 业务日期只有一个状态任务业务键，输入hash固定来源和会话；使用既有可靠执行器、咨询锁、TaskRun与有界重试，每轮至多既有max_replay_sessions（1—31）项。新导入不能重写已完成日期的历史。
- 报告提交前锁定并重验当前启用版本，避免暂停 / 换源窗口落下过时报告；报告事件、审计、Outbox和TaskRun成功同事务。配置竞争时不生成假报告，已记录的失败可见。
- 产品页面显示来源 / 时点 / hash、当前暂停状态、近30次实际任务与报告；没有任务不表示Worker健康，明确可能尚无到期会话、已暂停或Worker未运行。无外部来源读取、付费模型或订单调用。

## 兼容、替代与恢复

新迁移0015基于当前Release的0014；不采用未合并PR #18的同号链。新增三张正规化表，不用通用JSON替代日历状态。既有任务与报告历史不改。
拒绝默认启用真实研究、隐式工作日日历、按导入自动调用模型、借synthetic成功事件冒充正式分析。
撤回应用前暂停产品日历，旧应用保留新增表与全部历史；新迁移仅空表可downgrade，有历史时拒绝降级并采用前向修复，禁止删除记录。
验证只用独立15438 / 18110的合成输入和命名数据库，不操作所有者18102，不启用真实研究来源。新数据授权或真实定时研究仍需所有者明确边界。

主规范§5、14、16.3、17、18；PRODUCT-08范围1 / 2 / 7，MVP-401可见验收契约。

## 2026-10-27 独立Gate恢复审阅补充（本PR首次集成前）

独立审阅 [6434908997](https://github.com/zmd6s6/JZ-Investment-OS/pull/23#issuecomment-6434908997) 发现，原“每市场 / 日期单一TaskRun键”在失败后换源时会与旧input_hash永久冲突。上述键描述由本节明确更正，不更改已集成ADR或删除失败历史。
TaskRun尝试键包含市场 / 业务日期 / 不可变日历导入ID，来源修正产生独立尝试；同来源仍受既有3次重试上限约束。
跨来源的业务效果仍严格按市场 / 业务日期至多一次：计划时读取已提交报告，handler在TaskRun同事务 / 同连接内加业务日期咨询锁并再次核对成功报告，包括旧日期键生成的历史。
若已有成功则抛出预期竞争异常并回滚尚未提交的新TaskRun；不得直接return生成无报告的SUCCEEDED。当前配置仍须锁定重验，旧版本不能在换源后落地。
旧FAILED及已成功报告均保留。UI明确更正来源 / 重新启用恢复方式；集成与合成浏览器覆盖A失败→B恢复、已成功后换C不重复，以及不同版本并发。
